算法在做什么

      

        目标：把 n 个像素点 x₁…xₙ（每个是 d 维向量）分成 K 个簇 S₁…S_K，使簇内平方误差和最小：
      

      
J = Σ_{c=1..K} Σ_{x ∈ S_c} ‖x − μ_c‖²      ,  μ_c = (1/|S_c|) Σ_{x ∈ S_c} x

这是一个 NP-hard 问题的常用近似解，Lloyd 迭代（本页实现）交替做两件事：

  1) 分配 (Assignment)  x 归到最近的质心：  label(x) = argmin_c ‖x − μ_c‖²
  2) 更新 (Update)      质心 = 本簇所有点的均值： μ_c ← mean(S_c)

性质：每一步都不会让 J 变大 → J 单调不增，因此一定收敛（可能收敛到局部最优）。
所以初始化很关键：纯随机会经常收敛到很差的局部解，k-means++ 让初始质心尽量互相远离，
理论上把 J 的期望近似控制在最优解的 O(log K) 倍以内。

停止条件（本页实现，和主流库一致）：
  · 标签不再变化        → 真正收敛
  · 质心位移² ≤ tol     → 提前收工（tol 偶发早停：某一轮恰好只挪了一点点，不等于已经到底）
  · 迭代次数达到上限    → 强制停止
无论走哪一条，本页最后都会用当前标签再做一次"取均值"更新，然后按最终的 (labels, centroids)
重算 inertia。所以返回的三样东西永远严格自洽：
        centroids = 各簇均值      （可以自己按标签算一遍验证）
        inertia   = Σ‖x − μ_label(x)‖²
代价是极少数压在分界线上的点，其标签不是新质心的严格最近者（差最后一小步）。
sklearn 做的是相反的选择——标签严格取最近质心，于是 cluster_centers_ 偶尔不是 labels_ 的
精确均值。两者都不是 bug，只是"最后一步收在哪"的取舍。

k-means++ 播种（本页 initKMeansPlusPlus）：
  ① 均匀随机取第一个质心
  ② 计算每个点到"已有质心集合"的最近距离平方 D(x)²
  ③ 以正比于 D(x)² 的概率抽下一个质心（离得越远越容易被抽中）
  ④ 重复 ②③ 直到取满 K 个

空簇处理：某个簇一个点都没分到 → 把"离自己质心最远的那个点"抢过来（等价于 sklearn 的做法），
否则空簇的质心会退化并永远吸不到点。

图像上的两个变体（本页"特征模式"）：
  · 颜色 RGB / Lab ：只在颜色空间聚类 → 结果就是一张 K 色调色板的量化图（posterize / 减色）。
  · 颜色 + 位置 XY ：把像素坐标 (x/W, y/H) 乘空间权重后拼到颜色向量后面，共 5 维 →
    k-means 同时考虑"颜色像"和"位置近" → 得到连通的区域分割（SLIC 超像素的简化版就是这个思路）。

      
陷阱提醒：k-means 用的是欧氏距离，隐含假设簇是"各向同性、大小相近的球"；
        对细长、弯折、密度差异大的区域会切得很怪。另外 RGB 距离与人眼感知不一致——想更符合直觉就选 Lab。
